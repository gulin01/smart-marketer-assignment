# 작업 계획 — 템플릿 인앱 편집기 + 다국어

## A. 다국어 (i18n)

한국어 기본, 영어 전환. **URL은 바꾸지 않는다** — `/ko/admin` 같은 경로 세그먼트를
도입하면 모든 라우트·테스트·배포된 링크가 함께 바뀐다. 쿠키(`locale`)로 전환하고
서버 컴포넌트가 이를 읽는다.

- [x] `lib/i18n/` — 타입 안전 사전(ko/en), `getLocale()`, `t()`
- [x] API 오류 메시지도 같은 사전을 사용 (코드는 영문 유지)
- [x] 헤더에 언어 전환 버튼
- [x] 공개 폼(방문자 화면)은 한국어 고정 — 운영자 설정이 방문자에게 새지 않도록

## B. 템플릿 편집기

### 1. 데이터 모델
- [x] `TemplateVersion` 테이블 — `{ id, templateId, html, fieldNames, note, createdAt, createdById }`
- [x] `HtmlTemplate.updatedAt` 컬럼
- [x] 마이그레이션을 로컬 · 테스트 · **운영(Neon)** 에 모두 적용

### 2. API
- [x] `GET /api/templates/:id` — html + fieldNames + 버전 수 + 사용 중인 폼/캠페인 수
- [x] `PUT /api/templates/:id` — 저장. 서버에서 재파싱·검증, 버전 기록
- [x] `GET /api/templates/:id/versions` — 이력
- [x] `POST /api/templates/:id/versions/:versionId/restore` — 복원(자체도 새 버전 생성)
- [x] 필드 삭제 감지 → `confirm=true` 없이는 409 + 영향 정보 반환

### 3. UI
- [x] `/admin/templates/[id]/edit` — 좌측 코드 편집기, 우측 샌드박스 미리보기
- [x] CodeMirror 6 (Monaco 대비 번들이 훨씬 작다)
- [x] 400ms 디바운스, 내용이 실제로 바뀐 경우에만 `srcdoc` 갱신
- [x] 감지된 입력 필드 칩, 저장/취소, 이력 패널 + 복원
- [x] 저장 안 된 변경 이탈 경고
- [x] 템플릿 목록에 "편집" 버튼

### 4. 검증
- [x] 단위: 필드 변경 감지(추가/삭제/유지)
- [x] API: 저장·검증 실패·필드 삭제 확인 흐름·이력·복원
- [x] E2E: 운영 중인 폼의 템플릿을 편집 → 공개 폼에 즉시 반영

## 결정 사항 (§10 답변)

1. **여러 캠페인이 쓰는 템플릿** — 사용 중인 캠페인/폼 수를 항상 표시하되 저장을
   막지 않는다. 확인 모달은 *제출 데이터가 있는 필드가 사라질 때만* 띄운다.
   "2개 캠페인에서 사용 중" 정도로 매번 막으면 경고를 무시하는 습관만 생긴다.
2. **자동 저장** — 하지 않는다. 이 템플릿은 방문자에게 즉시 노출되므로, 타이핑
   중간 상태가 공개 폼에 반영되면 안 된다. 명시적 저장 + 이탈 경고.
3. **읽기 전용 권한** — 범위 밖. 운영자 계정은 설계상 1개다(ADR 0002).
