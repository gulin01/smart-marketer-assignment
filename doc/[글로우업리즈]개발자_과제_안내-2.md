# 글로우업리즈 개발자 과제 — Step-by-Step Plan

**Deadline:** 3 days from receipt. Plan below is split into 3 days + a buffer. The graders care about one thing: *the operator registers an HTML → makes a form → gets channel links → a visitor submits → the dashboard shows visits / visitors / submissions / conversion per campaign and per channel.* Everything else is secondary.

**Recommended stack (fast to ship, matches your React/TS background):**
- Next.js 14+ (App Router, TypeScript) — admin UI + API routes in one repo
- PostgreSQL + Prisma (schema + migrations required by the brief)
- Auth: `iron-session` (cookie session, single seeded operator) — simpler than NextAuth for this scope
- Tests: Vitest (unit/API) + Playwright (1–2 E2E flows)
- API docs: OpenAPI YAML (`docs/openapi.yaml`) + Swagger UI at `/api-docs`
- Deploy: Vercel + Neon/Supabase Postgres (optional demo URL — worth doing if time allows)

## Day 0 — Read, decide, scaffold (2–3 h)

### 0.1 Write assumptions first (they become ADRs)
Note these before coding; each one is an ADR later:
1. **One operator account**, seeded via env (`ADMIN_EMAIL`, `ADMIN_PASSWORD`). No signup.
2. **Channels are fixed:** `instagram | x | youtube | threads`. A "distribution link" = `/f/{formSlug}?ch={channel}` (or `/f/{slug}/{channel}`).
3. **Visit** = every page load of the public form. **Visitor** = unique `visitor_id` cookie (UUID, 1st-party, 1-year). **Submission** = successful POST. **Conversion rate** = submissions ÷ visitors (state this explicitly; some use visits).
4. **HTML template ↔ form contract:** the uploaded HTML must contain a `<form>` with named inputs. The platform injects a hidden `formId`/`channel` and a small submit script; the raw HTML is never executed in the admin origin.
5. **Submission storage:** answers stored as `jsonb` (`{fieldName: value}`) because forms are custom; `name/phone/email` extracted into columns when field names match, for CRM listing.
6. **Isolation:** public form is served from a *separate route + separate host* (`FORM_HOST` env, e.g. `forms.localhost:3001` or a Vercel second domain) inside a sandboxed `<iframe sandbox="allow-forms allow-scripts">` with a strict CSP. Admin API rejects any request lacking the session cookie, and the session cookie is `SameSite=Strict` + host-scoped, so the form origin can never carry it.

## Day 1 — Data model, auth, template upload, form creation

### 1.1 Prisma schema
```prisma
model Operator     { id String @id @default(cuid()); email String @unique; passwordHash String; createdAt DateTime @default(now()) }

model HtmlTemplate { id String @id @default(cuid()); name String; html String; fieldNames String[]; createdAt DateTime @default(now()); forms Form[] }

model Campaign     { id String @id @default(cuid()); name String; description String?; createdAt DateTime @default(now()); forms Form[] }

model Form {
  id String @id @default(cuid()); slug String @unique; title String
  campaignId String; campaign Campaign @relation(...)
  templateId String; template HtmlTemplate @relation(...)
  isActive Boolean @default(true); createdAt DateTime @default(now())
  links DistributionLink[]; visits Visit[]; submissions Submission[]
}

enum Channel { INSTAGRAM X YOUTUBE THREADS }

model DistributionLink { id String @id @default(cuid()); formId String; channel Channel; url String; createdAt DateTime @default(now()); @@unique([formId, channel]) }

model Visit      { id String @id @default(cuid()); formId String; channel Channel?; visitorId String; userAgent String?; createdAt DateTime @default(now()); @@index([formId, channel]); @@index([formId, visitorId]) }

model Submission { id String @id @default(cuid()); formId String; channel Channel?; visitorId String?; name String?; phone String?; email String?; data Json; createdAt DateTime @default(now()); @@index([formId, channel]) }
```
```bash
npx prisma migrate dev --name init
```
Write `prisma/seed.ts` that upserts the operator from env (bcrypt hash).

### 1.2 Auth
- `POST /api/auth/login` → verify bcrypt → set iron-session cookie (`httpOnly`, `secure` in prod, `sameSite: 'strict'`).
- `POST /api/auth/logout`, `GET /api/auth/me`.
- `middleware.ts`: redirect `/admin/*` → `/login` when no session; return 401 for `/api/*` except `/api/auth/login` and `/api/public/*`.
- Login page (`/login`).

### 1.3 HTML template registration
- `POST /api/templates` (multipart or JSON `{name, html}`):
  - Accept only `.html`, size ≤ 200 KB.
  - Parse with `cheerio` (`npm i cheerio`): require exactly one `<form>`; collect `input/select/textarea` `name` attributes → `fieldNames`. Reject if no named fields.
  - Store raw HTML (do **not** try to sanitize it into safety — isolation is by origin/iframe, record this in the ADR).
- `GET /api/templates`, `GET /api/templates/:id`.
- Admin page `/admin/templates` with upload + preview (preview rendered in the same sandboxed iframe as production).

### 1.4 Campaign + custom form creation
- `POST /api/campaigns`, `GET /api/campaigns`.
- `POST /api/forms` `{campaignId, templateId, title, slug?}` → slug auto-generated (`nanoid(8)`) if omitted.
- On form creation, **auto-generate the 4 DistributionLinks** (`${FORM_HOST}/f/${slug}?ch=instagram` etc.) so the operator sees them immediately. Also expose `POST /api/forms/:id/links` for regeneration.
- Admin pages: `/admin/campaigns`, `/admin/campaigns/[id]` (forms list + "create form" modal), `/admin/forms/[id]` (links with copy buttons, submissions table).

**End of Day 1 checkpoint:** log in → upload HTML → create campaign → create form → see 4 links.

## Day 2 — Public form, tracking, submissions, dashboard

### 2.1 Public form page `/f/[slug]`
- Server component: load form + template; 404 if missing/inactive.
- Read `ch` query → validate against enum (invalid → `null`, still works).
- Ensure `visitor_id` cookie exists (set in a route handler or middleware for `/f/*`).
- **Record a Visit** (formId, channel, visitorId, UA). Do it in the page's server code, wrapped in try/catch so a DB hiccup never breaks the form.
- Render page shell: the *page* is yours; the *template* is embedded via
  `<iframe sandbox="allow-forms allow-scripts" src="/f/[slug]/render?ch=…">`.
- `/f/[slug]/render` route returns the raw template HTML with two injections (string ops via cheerio):
  1. `<input type="hidden" name="__channel" value="…">` inside the form
  2. A tiny script that intercepts `submit`, serializes the form to JSON, and `fetch`es `POST /api/public/forms/[slug]/submissions`, then swaps the form for a thank-you message.
  Set headers: `Content-Security-Policy: default-src 'self'; form-action 'self'; frame-ancestors ${APP_HOST}`, `X-Frame-Options` omitted (CSP covers it), no session cookie is ever read here.

### 2.2 Public submission API
- `POST /api/public/forms/[slug]/submissions`:
  - Zod-validate body: object of string values, keys ⊆ `template.fieldNames` (extra keys → 400).
  - Rate limit by IP + slug (simple in-memory LRU or a `RateLimit` table; ~10/min).
  - Extract `name/phone/email` if present.
  - Insert Submission; return `201 {id}`.
  - Failure cases to handle: unknown slug (404), inactive form (410), invalid body (400), rate limited (429).
- No auth, no CSRF token needed (cross-origin POST from the form host is expected — accept `Origin === FORM_HOST` only).

### 2.3 Stats service (`lib/stats.ts`)
Single SQL per campaign (Prisma `$queryRaw` is fine):
```sql
SELECT f.campaign_id,
       COUNT(v.id)                       AS visits,
       COUNT(DISTINCT v.visitor_id)      AS visitors,
       (SELECT COUNT(*) FROM "Submission" s JOIN "Form" f2 ON f2.id = s.form_id WHERE f2.campaign_id = f.campaign_id) AS submissions
FROM "Form" f LEFT JOIN "Visit" v ON v.form_id = f.id
GROUP BY f.campaign_id;
```
conversion = submissions / visitors (0 when visitors = 0). Same query grouped by `channel` for channel stats.
- `GET /api/stats/campaigns` → list with visits, visitors, submissions, conversionRate.
- `GET /api/stats/campaigns/:id/channels` → per-channel breakdown.
- Optional `?from=&to=` date filter.

### 2.4 Admin dashboard
- `/admin` : campaign table (visits / visitors / submissions / conversion %).
- `/admin/campaigns/[id]` : channel table + bar chart (recharts) + forms list.
- `/admin/forms/[id]/submissions` : CRM list (name, phone, email, channel, date, expand JSON), CSV export button (`GET /api/forms/:id/submissions?format=csv`).

**End of Day 2 checkpoint:** open a link in an incognito window → submit → dashboard numbers move. Run this manually with 2 channels to verify channel attribution.

## Day 3 — Security hardening, tests, docs, submission

### 3.1 Security checklist (map to 비기능 요구사항 #1)
- [ ] Session cookie: `httpOnly`, `sameSite=strict`, `path=/`, scoped to APP_HOST.
- [ ] Public form served at a different origin (FORM_HOST) in prod; in dev, still iframe-sandboxed.
- [ ] Iframe `sandbox` without `allow-same-origin` → template JS has an opaque origin; cannot read admin cookies or `localStorage`.
- [ ] CSP on the render route.
- [ ] Every `/api/*` non-public route checks session (write one `requireSession()` helper and use it everywhere).
- [ ] Public submission endpoint validates `Origin`.
- [ ] Template upload rejects non-HTML, oversized, and formless files.
- [ ] Write an explicit negative test: a template containing `<script>fetch('/api/stats/campaigns')</script>` must get 401 (test the API directly with no cookie) and, in E2E, must not be able to read `document.cookie` of the parent.

### 3.2 Automated tests (success + failure flows)
**Unit (Vitest)**
- `stats.ts`: visitors dedup, conversion rounding, zero-division.
- `sanitize/parse`: field extraction, formless HTML rejected.

**API (Vitest + test DB, `DATABASE_URL_TEST`)**
- Login success / wrong password (401) / no session on `/api/campaigns` (401).
- Template upload: valid (201), non-html (400), no `<form>` (400).
- Form creation generates 4 links with correct channel query.
- Public submission: valid (201), unknown slug (404), inactive (410), unknown field (400), rate limit (429).
- Stats: seed 3 visits (2 visitors) + 1 submission → visitors=2, conversion=0.5; channel split correct.

**E2E (Playwright, 1 spec)**
- Operator login → upload template → create campaign+form → copy instagram link → new context visits it → submits → dashboard shows 1/1/1/100% and instagram row = 1.
