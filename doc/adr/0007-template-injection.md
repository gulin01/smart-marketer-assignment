# ADR 0007 — 템플릿에 채널·방문자 히든 필드와 제출 스크립트를 주입

- 상태: 채택
- 날짜: 2026-09-11

## 배경

운영자가 올린 HTML의 `<form>` 은 플랫폼을 모른다. 어디로 제출해야 하는지, 어떤
채널로 유입되었는지, 누가 보고 있는지 알 수 없다. 운영자에게 특정 `action` 이나
숨은 필드를 요구하면 "HTML 파일만 올리면 된다" 는 전제가 깨진다.

## 결정

렌더 시점에 cheerio로 원본 HTML을 파싱해 세 가지를 주입한다.

1. `<input type="hidden" name="__channel" value="…">` — URL의 `?ch=` 에서 확정
2. `<input type="hidden" name="__visitor" value="…">` — 서버가 읽은 쿠키 값
3. 제출 가로채기 스크립트 — `submit` 을 가로채 폼을 JSON으로 직렬화하고
   제출 API에 `fetch` 한 뒤, 성공하면 폼을 감사 메시지로 교체한다

`__` 접두사는 플랫폼 예약어다. 템플릿 파싱 단계에서 `__` 로 시작하는 필드명은
`fieldNames` 에서 제외되므로, 운영자가 같은 이름을 써도 응답으로 취급되지 않는다.

**방문자 식별자를 쿠키가 아닌 히든 필드로 보내는 이유**: iframe이 불투명 출처를
가지므로([[0003]]) 그 안의 `fetch` 는 쿠키를 전혀 싣지 않는다. 서버가 렌더 시점에
쿠키를 읽어 문서 안에 심어주는 것이 유일한 경로다.

## 결과

- 운영자는 평범한 `<form>` 하나가 있는 HTML만 올리면 된다.
- 원본 마크업은 보존된다. 주입은 추가일 뿐 수정이 아니다.
- 제출이 `fetch` 로 이뤄지므로 페이지 이동 없이 완료되고, CSP의
  `form-action 'none'` 과도 충돌하지 않는다.
- 히든 필드 값은 HTML 이스케이프한다. 그렇지 않으면 방문자 식별자가 속성을
  탈출할 수 있다 (`tests/unit/inject.test.ts` 가 이를 고정).
- 채널과 방문자 값은 클라이언트를 거치므로 조작 가능하다. 분석 지표의 성격상
  허용 가능한 위험으로 판단했다 ([[0006]], [[0008]]).
- 템플릿에 `<form>` 이 없으면 주입 없이 원본을 그대로 반환한다. 업로드 단계에서
  이미 거르므로 도달하지 않지만, 방어적으로 처리한다.
