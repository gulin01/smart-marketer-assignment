# ADR 0003 — HTML 격리: 정화(sanitize)가 아닌 오리진 분리 + 샌드박스 + CSP

- 상태: 채택
- 날짜: 2026-09-11

## 배경

운영자가 **임의의 HTML 파일**을 업로드하고, 그것이 방문자에게 그대로 렌더링된다.
이 HTML에는 `<script>` 가 포함될 수 있다. 비기능 요구사항 1번은 이 스크립트가
플랫폼의 관리 기능에 접근하지 못하도록 요구한다.

핵심 위협: 업로드된 템플릿이 `fetch('/api/stats/campaigns')` 로 다른 고객의 리드를
읽거나, `document.cookie` 로 운영자 세션을 탈취하는 것.

## 결정

HTML을 **수정하지 않고 원본 그대로 저장**한다. 격리는 렌더링 시점에 네 겹으로 건다.

1. **별도 오리진** — 공개 폼은 `FORM_HOST` 에서 서빙한다. 운영 환경에서는 관리
   화면(`APP_HOST`)과 다른 도메인이어야 한다. 세션 쿠키는 `APP_HOST` 에 호스트
   스코프로 묶여 있으므로 폼 오리진에서는 존재조차 하지 않는다.
2. **샌드박스 iframe** — 템플릿은 `sandbox="allow-forms allow-scripts"` iframe
   안에서만 실행된다. **`allow-same-origin` 을 주지 않는 것이 핵심**이다. 이로써
   문서는 불투명 출처(opaque origin)를 갖고, 쿠키·localStorage에 접근할 수 없으며
   부모 문서에 접근하면 예외가 발생한다.
3. **CSP** — 렌더 라우트는 `default-src 'self'`, `connect-src {FORM_HOST}`,
   `form-action 'none'`, `frame-ancestors {FORM_HOST} {APP_HOST}` 를 내려보낸다.
   외부로의 유출 경로와 폼 액션 탈취를 차단한다.
4. **서버 측 인증 검사** — `/api/public/*` 과 로그인을 제외한 모든 API가
   `requireSession()` 을 호출한다. 위 세 겹이 모두 뚫려도 401이다.

렌더 라우트는 세션 쿠키를 **읽지 않는다**.

## 결과

- 운영자의 HTML이 의도대로 동작한다. 정화 방식이었다면 정상적인 랜딩 페이지의
  애니메이션·분석 스크립트까지 조용히 망가뜨렸을 것이다.
- 템플릿 스크립트는 실제로 실행된다. 이것은 버그가 아니라 설계다 — 신뢰 경계는
  "실행 여부" 가 아니라 "무엇에 접근 가능한가" 에 그어져 있다.
- 불투명 출처의 부작용: iframe이 쿠키를 보내지 못하므로, 방문자 식별자를 쿠키가
  아닌 주입된 히든 필드로 전달해야 한다 ([[0007]]).
- 마찬가지로 제출 요청의 `Origin` 은 항상 `null` 이다. 엔드포인트는 `null`,
  `FORM_HOST`, `APP_HOST` 만 허용하고 CORS 프리플라이트에 응답한다.
- 개발 환경에서는 `APP_HOST === FORM_HOST` 이므로 1번 방어선이 없다. 나머지
  세 겹은 그대로 동작하며, 이 사실을 README에 명시했다.

## 검증

- `tests/api/security.test.ts` — 세션 없는 관리 API는 모두 401이고 응답 본문에
  데이터가 새지 않는다. 렌더 라우트의 CSP 지시자와 "세션 쿠키 미설정" 을 검사한다.
- `tests/e2e/template-isolation.spec.ts` — **운영자가 로그인한 실제 브라우저**에서
  악성 템플릿을 렌더링하고, 쿠키를 읽지 못하며 부모 문서 접근이 차단되고
  관리 API 호출이 200을 받지 못함을 확인한다.

## 검토한 대안

- **DOMPurify 등으로 정화** — 운영자 HTML을 훼손한다. 또한 정화기는 우회 사례가
  꾸준히 보고되는 반면, 불투명 출처는 브라우저가 강제하는 경계다.
- **`<script>` 제거** — 위와 같은 이유로 기각. 정상 기능까지 제거된다.
- **iframe 없이 직접 삽입** — 같은 문서에서 실행되므로 방어 수단이 사실상 없다.
