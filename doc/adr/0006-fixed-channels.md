# ADR 0006 — 고정 4채널과 `?ch=` 링크 형식

- 상태: 채택
- 날짜: 2026-09-11

## 배경

과제는 인스타그램 · X · 유튜브 · 스레드 네 채널의 배포 링크를 요구한다. 링크로
유입된 방문과 제출이 채널별로 집계되어야 한다.

## 결정

채널을 DB `enum Channel { INSTAGRAM X YOUTUBE THREADS }` 으로 고정한다.
배포 링크 형식은 `{FORM_HOST}/f/{slug}?ch={channel}` 이다.

폼을 생성하면 **네 개의 링크가 자동 생성**된다. 운영자가 링크 없는 폼을 마주하는
중간 상태가 없다. `(formId, channel)` 에 유니크 제약을 두어 중복을 막는다.
`POST /api/forms/:id/links` 는 upsert 이므로 재생성해도 링크가 늘지 않는다.

알 수 없는 `ch` 값은 **오류가 아니라 `null`** 로 처리한다.

## 결과

- enum이므로 오타난 채널이 DB에 들어갈 수 없고, 집계 쿼리가 네 채널을 항상 반환한다.
- 채널 추가는 마이그레이션을 요구한다. 네 개가 요구사항으로 고정되어 있으므로
  이 비용은 타당하다. 자유 문자열이었다면 `Instagram`/`instagram`/`ig` 가 섞여
  집계가 조용히 갈라졌을 것이다.
- `?ch=` 쿼리 방식은 경로 방식(`/f/{slug}/{channel}`)과 달리 채널 없는 직접 방문이
  자연스럽게 같은 URL로 처리된다. 이 트래픽은 `channel = null` 로 기록되고
  대시보드에 "직접 유입" 행으로 나타난다.
- 방문자가 URL의 `ch` 를 임의로 고쳐도 폼은 정상 동작한다. 잘못된 값은 무시된다.
- 채널 값은 방문자가 조작할 수 있다. 리드 귀속은 분석용이지 보안 경계가 아니다.

## 검증

`tests/api/forms.test.ts` 가 폼 생성 시 링크 4개와 각 링크의 `ch` 파라미터를,
`tests/unit/channels.test.ts` 가 파싱 관용성과 왕복 변환을 고정한다.
