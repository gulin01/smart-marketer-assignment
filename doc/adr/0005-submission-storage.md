# ADR 0005 — 제출 데이터 저장: JSONB + 추출된 CRM 컬럼

- 상태: 채택
- 날짜: 2026-09-11

## 배경

폼은 운영자가 업로드한 HTML에서 나오므로 필드 구성이 매번 다르다. 반면 CRM
목록에서는 이름·연락처·이메일을 컬럼으로 정렬하고 검색할 수 있어야 한다.

## 결정

응답 전체를 `Submission.data` (jsonb)에 저장한다. 동시에 필드명이 알려진 패턴과
일치하면 `name`, `phone`, `email` 컬럼에 복사한다.

패턴은 영문과 한글을 모두 포함한다 (`name|이름|성함`, `phone|연락처|휴대폰`,
`email|이메일` 등). 한 컬럼에 여러 필드가 매칭되면 **처음 매칭된 값**을 쓴다.

제출 API는 `data` 의 키가 템플릿이 선언한 `fieldNames` 의 부분집합인지 검사하고,
아니면 400을 반환한다.

## 결과

- 어떤 폼이든 응답이 손실 없이 보존된다.
- CRM 목록과 CSV가 임의 폼에서도 동일한 컬럼 구조를 갖는다.
- 추출은 **휴리스틱**이다. 필드명이 `contact_number` 라면 `phone` 컬럼이 비고,
  값은 `data` 에만 남는다. 목록 UI가 전체 JSON을 펼쳐 볼 수 있게 한 이유다.
- 키 화이트리스트 덕분에 제출 엔드포인트가 임의 JSON 저장소로 악용되지 않는다.
- CSV는 CRM 컬럼과 원본 응답을 모두 내보내되, 원본에는 `answer.` 접두사를 붙여
  같은 이름의 컬럼이 중복되지 않게 한다. 엑셀의 수식 주입(`=`, `+`, `-`, `@` 로
  시작하는 값)은 작은따옴표로 무력화하고, 한글이 깨지지 않도록 UTF-8 BOM을 붙인다.

## 검토한 대안

- **폼마다 테이블 생성** — 조회는 빠르지만 폼을 만들 때마다 DDL이 필요하다.
- **EAV (키-값 행)** — 유연하지만 한 건을 읽는 데 조인이 필요하고 `jsonb` 보다
  이점이 없다.
- **JSONB만 저장** — CRM 목록에서 매번 JSON을 파싱해야 하고 정렬·색인이 번거롭다.
