# ADR 0002 — 운영자 1계정, JWT 대신 쿠키 세션

- 상태: 채택
- 날짜: 2026-09-11

## 배경

과제는 "운영자가 로그인한다" 까지만 요구한다. 회원가입, 권한 분리, 다중 테넌시는
범위 밖이다. 그러나 인증이 뚫리면 모든 리드 데이터가 노출되므로 부실하게 만들 수 없다.

## 결정

운영자 계정 1개를 환경변수(`ADMIN_EMAIL`, `ADMIN_PASSWORD`)로 시드하고,
`iron-session` 기반의 암호화된 쿠키 세션을 사용한다. 공개 가입 경로는 없다.

쿠키 속성: `httpOnly`, `sameSite=strict`, 운영 환경에서 `secure`, `path=/`, 8시간 만료.

## 결과

- **`httpOnly`** — 템플릿 스크립트가 `document.cookie` 로 세션을 읽을 수 없다.
- **`sameSite=strict`** — 다른 오리진에서 출발한 요청에 쿠키가 실리지 않는다.
  공개 폼이 별도 호스트에 있을 때 관리 API를 호출해도 인증되지 않는다 ([[0003]]).
- **서버 측 무효화** — 세션 파기가 즉시 반영된다. JWT였다면 만료까지 유효하거나
  블랙리스트 저장소가 필요했다.
- 비밀번호는 bcrypt로 해싱한다. 로그인 실패 시 계정 존재 여부와 무관하게 동일한
  메시지와 응답 시간을 반환한다(존재하지 않는 계정도 더미 해시와 비교).

## 검토한 대안

- **JWT** — 상태가 없어 확장에 유리하지만, 운영자가 1명인 시스템에서 얻을 이득이
  없고 로그아웃 즉시 무효화가 어렵다.
- **NextAuth** — 다중 프로바이더를 위한 도구다. 계정 하나에는 설정 비용이 더 크다.
- **HTTP Basic** — 로그아웃 개념이 없고 자격증명이 매 요청 전송된다.
