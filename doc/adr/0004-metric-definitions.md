# ADR 0004 — 방문 · 방문자 · 전환율의 정의

- 상태: 채택
- 날짜: 2026-09-11

## 배경

과제는 "방문 수, 방문자 수, 제출 수, 전환율" 을 요구하지만 각각의 정의는 주지
않았다. 정의를 적어두지 않으면 같은 화면을 보는 두 사람이 다른 숫자를 이해한다.

## 결정

| 지표 | 정의 |
|---|---|
| **방문 (visit)** | 공개 폼 페이지가 로드될 때마다 1건. 같은 사람이 5번 열면 5건. |
| **방문자 (visitor)** | `visitor_id` 쿠키 기준 고유 수. UUID v4, 1년 만료, 퍼스트파티. |
| **제출 (submission)** | 제출 API가 201을 반환한 건수. |
| **전환율** | **제출 ÷ 방문자**. 방문자가 0이면 0. 소수점 4자리에서 반올림. |

`visitor_id` 쿠키는 `proxy.ts` 에서 발급한다 — 서버 컴포넌트는 쿠키를 설정할 수
없기 때문이다. 발급과 동시에 해당 요청에도 반영해, 첫 방문이 누락되지 않는다.

방문 기록은 `try/catch` 로 감싼다. 집계가 실패해도 방문자에게 폼은 떠야 한다.

## 결과

- **분모를 방문자로 택한 이유** — 한 사람이 페이지를 새로고침해 전환율이 희석되면
  채널 비교가 왜곡된다. 방문 기준 전환율이 필요하면 `visits` 가 함께 제공되므로
  대시보드에서 파생할 수 있다.
- 전환율이 1을 넘을 수 있다. 같은 방문자가 여러 번 제출하면 그렇게 된다.
  제출을 중복 제거하지 않기로 했으므로([[0008]]) 이 값을 그대로 노출한다 —
  1로 깎으면 실제로 일어난 일을 숨기게 된다.
- 쿠키를 차단한 방문자는 방문자 수에 잡히지 않는다. 제출은 기록되되 `visitorId`
  가 비고, 해당 채널의 전환율이 실제보다 높게 보일 수 있다.
- 대시보드 화면에 정의를 함께 표기해 해석 차이를 줄였다.

## 검증

`tests/unit/stats.test.ts` 가 0으로 나누기, 반올림, 1 초과 사례를 고정한다.
`tests/api/stats.test.ts` 는 방문 3건·방문자 2명·제출 1건 → 전환율 0.5를 확인한다.
