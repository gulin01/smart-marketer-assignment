## 문제

템플릿은 완성된 `.html` 업로드로만 등록할 수 있다. 오타 하나를 고치려 해도 로컬에서
편집해 다시 올려야 하고, 그러면 **새 템플릿 행**이 생긴다. 기존 폼은 예전 내용을
계속 서빙하므로 운영자가 폼을 일일이 다시 연결해야 한다.

## 목표

운영자가 브라우저에서 템플릿 HTML 을 고치고 저장하면, 그 템플릿을 쓰는 모든 폼이
즉시 새 내용을 서빙한다. 잘못 고쳤으면 이전 버전으로 되돌릴 수 있다.

## 범위

**포함**
- 편집 페이지 — 좌측 코드 편집기, 우측 샌드박스 실시간 미리보기
- 제자리 저장 (같은 id 유지)
- 저장 시 검증 — `<form>` 1개, 이름 있는 필드
- 버전 기록과 복원
- 입력 필드가 사라지는 저장은 확인 후 진행

**제외**
- WYSIWYG — 임의 HTML 을 구조화 모델로 왕복시키면 원본이 손상된다. 원본 보존은
  격리 전략의 전제 (ADR 0003)
- 실시간 공동 편집 — 운영자 계정이 1개다 (ADR 0002)
- 에디터 내 에셋 업로드

## 동작

### 성공 경로
1. 템플릿 목록에서 **편집**을 누른다.
2. 좌측에 현재 HTML, 우측에 렌더링된 결과가 보인다.
3. 타이핑하면 미리보기가 잠시 뒤 따라온다.
4. 감지된 입력 필드가 칩으로 갱신된다.
5. **저장**하면 그 템플릿을 쓰는 모든 폼이 즉시 새 내용을 서빙한다.
6. **변경 이력**에서 이전 버전으로 복원할 수 있다.

### 실패 경로
| 상황 | 결과 |
|---|---|
| `<form>` 이 사라짐 | 400 — 저장되지 않고 기존 내용 유지 |
| `<form>` 2개 이상 | 400 |
| 이름 있는 필드 없음 | 400 |
| 200 KB 초과 | 400 |
| **데이터가 있는 필드가 사라짐** | 409 + 삭제될 필드·영향 제출 건수 → 확인 후 진행 |
| 다른 템플릿의 버전으로 복원 시도 | 404 |
| 세션 없음 | 401 |
| 저장 안 한 채 이탈 | 브라우저 확인 |

## 성공 기준

- [x] 편집 저장 후 **공개 폼**이 새 내용을 서빙한다 (재연결 없이)
- [x] 저장할 때마다 직전 내용이 버전으로 남는다
- [x] 복원이 덮어쓰는 내용도 버전으로 남아, 복원을 되돌릴 수 있다
- [x] 필드 삭제 시 영향 건수를 보여주고 확인을 받는다
- [x] 이미 수집된 응답은 필드가 사라져도 보존된다
- [x] 미리보기는 운영과 **동일한 샌드박스**에서 렌더링된다
