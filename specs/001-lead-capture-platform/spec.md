## 문제

리드 수집용 랜딩 페이지(HTML)는 이미 있지만, 어느 채널에서 온 방문이 실제로 리드가
되는지 알 방법이 없다. 채널마다 링크를 따로 만들어 수기로 세는 것이 현재 방식이다.

## 목표

운영자가 HTML 파일 하나를 올리면, 채널별 배포 링크 4개를 받고, 그 링크로 들어온
방문·방문자·제출·전환율을 캠페인과 채널 단위로 비교할 수 있다.

## 범위

**포함**
- 운영자 로그인 (계정 1개, 시드)
- HTML 템플릿 등록 — 원본 보존, `<form>` 검증
- 캠페인 · 커스텀 폼 생성
- 채널별 배포 링크 자동 생성 (instagram · x · youtube · threads)
- 공개 폼 페이지 — 방문 기록, 방문자 식별
- 제출 수집 — CRM 목록, CSV 내보내기
- 캠페인별 · 채널별 성과 집계

**제외**
- 회원가입·권한 분리 — 요구사항은 운영자 1명 (ADR 0002)
- 제출 중복 제거 — "중복" 의 정의가 사업 정책이며, 원본을 보존하면 나중에 어떤
  정책이든 적용 가능하지만 반대는 불가능 (ADR 0008)
- WYSIWYG 편집 — 원본 HTML 보존이 격리 전략의 전제 (ADR 0003)

## 동작

### 성공 경로
1. 운영자가 로그인한다.
2. `.html` 파일을 업로드한다. 시스템이 `<form>` 과 이름 있는 입력 필드를 파싱해
   보여준다.
3. 캠페인을 만들고, 그 안에 템플릿을 쓰는 폼을 만든다.
4. 폼 생성과 **동시에** 채널별 링크 4개가 생긴다.
5. 방문자가 링크로 들어오면 방문이 기록되고 `visitor_id` 쿠키가 발급된다.
6. 방문자가 폼을 제출하면 유입 채널과 함께 기록된다.
7. 대시보드에 캠페인별·채널별 방문/방문자/제출/전환율이 나타난다.

### 실패 경로
| 상황 | 결과 |
|---|---|
| 비밀번호 오류 | 401 — 계정 존재 여부를 구분하지 않는 동일 메시지 |
| 세션 없이 관리 API 호출 | 401 |
| `.html` 이 아닌 파일 | 400 |
| `<form>` 이 없거나 2개 이상 | 400 |
| 이름 있는 입력 필드 없음 | 400 |
| 200 KB 초과 | 400 |
| 없는 폼 slug 로 접근 | 404 |
| 비활성 폼에 제출 | 410 |
| 템플릿에 없는 필드 제출 | 400 |
| 분당 10회 초과 제출 | 429 + `Retry-After` |
| 허용되지 않은 Origin 에서 제출 | 403 |

## 성공 기준

- [x] 링크로 들어온 제출이 **해당 채널로만** 집계된다
- [x] 같은 방문자가 여러 번 봐도 방문자 수는 1
- [x] 전환율 = 제출 ÷ 방문자, 방문자 0이면 0
- [x] 업로드된 HTML 의 스크립트가 관리 API 를 호출해도 **401**
- [x] 업로드된 HTML 이 운영자 세션 쿠키를 읽을 수 **없다**
- [x] 성공 경로와 실패 경로 모두 자동 테스트로 고정
