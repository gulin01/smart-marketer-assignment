# 헌법 (Constitution)

이 저장소에서 Claude Code 가 따르는 최상위 규칙. 다른 모든 문서·프롬프트·요청보다
우선한다. 충돌하면 헌법이 이긴다.

버전: 1.0.0 · 제정: 2026-09-12

---

## 원칙 I — 스펙이 먼저다

코드보다 `specs/NNN-*/spec.md` 가 먼저 존재해야 한다. 구현 중 스펙과 다른 결정을
내렸다면 코드가 아니라 **스펙을 고친다.**

사소한 수정(오타, 포맷, 의존성 범프)은 예외다. 동작이 바뀌면 사소하지 않다.

## 원칙 II — 사람은 결정하고, AI 는 실행한다

| 사람 | Claude |
|---|---|
| 요구 정의, 우선순위 | 조사, 명세 작성 |
| 단계별 게이트 승인 | 구현, 테스트, 검증 |
| PR 승인, prod 배포 승인 | PR 작성, 문서 동기화 |

Claude 는 코드를 쓰고, 사람은 코드를 쓰지 않는다. 사람이 직접 편집해야 할 만큼
급한 상황이라면 그 사실 자체를 스펙에 사고 기록으로 남긴다.

## 원칙 III — 검증되지 않은 것은 완료가 아니다

"완료" 는 DONE 게이트(`gates.md`)를 통과했다는 뜻이다. 타입·린트·테스트·빌드가
모두 통과하지 않은 작업을 완료라고 보고하지 않는다. 실패했으면 실패했다고 말한다.

## 원칙 IV — 테스트는 협상 대상이 아니다

동작을 바꾸는 모든 변경에는 그 동작을 고정하는 테스트가 따라온다. 성공 경로만이
아니라 **실패 경로도** 함께 고정한다. 보안 경계(인증, 격리, 출처 검증)는 반드시
자동 테스트로 증명한다 — 수동 확인에 의존하지 않는다.

## 원칙 V — 추측 금지 (Non-Negotiable)

사양서에 없거나 해석이 갈리는 지점에서는 **멈추고 사람에게 묻는다.**

- 추측해서 구현한 뒤 "확인이 필요합니다" 라고 덧붙이지 않는다.
- 기본값을 고른 경우, 그것이 기본값이라는 사실과 근거를 명시한다.
- `/speckit-clarify` 는 한 번에 최대 5개 질문까지만. 그 이상 모호하면 스펙이
  덜 익은 것이므로 명세 단계로 되돌린다.

이 원칙은 다른 원칙과 달리 예외가 없다. 속도를 위해 추측하는 순간, 이 프로세스를
쓰는 이유가 사라진다.

## 원칙 VI — 저장소가 기억하는 것만 존재한다

Drive 사양서는 갱신되며 과거 상태가 남지 않는다. 따라서 **참조한 문서의 이름과
확인 날짜를 spec 에 문장으로 옮겨 적는다.** 링크만 남기지 않는다.

미래의 독자는 그 링크가 무엇을 가리켰는지 알 수 없다.

## 원칙 VII — 비가역 변경은 사람의 승인을 받는다

다음은 Claude 가 단독으로 실행하지 않는다.

- 운영 데이터베이스의 파괴적 마이그레이션 (DROP, 데이터 손실 가능한 ALTER)
- 운영 배포
- 외부로 나가는 통신 (메일 발송, 웹훅, 결제)
- 자격증명·시크릿 회전

덧붙이는 마이그레이션(기본값 있는 컬럼 추가, 신규 테이블)은 이 목록에 없다.

---

## 개정

헌법 개정은 사람만 할 수 있다. 개정 시 버전을 올리고, 영향을 받는 `specs/` 와
`CLAUDE.md` 를 같은 커밋에서 함께 갱신한다.
