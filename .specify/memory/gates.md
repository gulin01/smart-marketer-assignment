# 게이트 (Gates)

각 단계에서 다음 단계로 넘어가기 전 통과해야 하는 조건.

---

## SPEC 게이트 — 명세 → 계획

- [ ] 사용자에게 보이는 동작이 서술되어 있다 (구현 방법이 아니라)
- [ ] 성공 기준이 **측정 가능**하다 ("빠르게" 가 아니라 "p95 < 300ms")
- [ ] 범위 밖 항목이 명시되어 있다
- [ ] 참조한 사양서 이름과 확인 날짜가 적혀 있다 (헌법 VI)
- [ ] 열린 질문이 없다 — 있다면 `/speckit-clarify` 로 해소하거나 스펙에 결정으로 기록

## PLAN 게이트 — 계획 → 작업

- [ ] 데이터 모델 변경이 명시되어 있다 (마이그레이션 포함)
- [ ] API 계약이 정의되어 있다 (경로, 요청/응답, 오류 코드)
- [ ] 헌법 원칙과 충돌하는 지점이 없다 — 있다면 근거와 함께 기록
- [ ] 되돌리는 방법이 있다

## TASKS 게이트 — 작업 → 구현

- [ ] 각 작업이 독립적으로 검증 가능하다
- [ ] 구현 순서가 의존성을 따른다 (아래 참조)
- [ ] 각 작업에 대응하는 테스트가 계획되어 있다

## DONE 게이트 — 구현 → PR

PR 을 올리기 전 **전부** 통과해야 한다.

```bash
npm run typecheck   # 타입 오류 0
npm run lint        # 오류 0, 경고 0
npm test            # 단위 + API
npm run test:e2e    # 브라우저 E2E
npm run build       # 프로덕션 빌드
```

추가로:

- [ ] 새 동작에 성공 경로 **와 실패 경로** 테스트가 있다 (헌법 IV)
- [ ] 보안 경계를 건드렸다면 그것을 증명하는 테스트가 있다
- [ ] 스펙과 구현이 어긋났다면 스펙을 갱신했다 (헌법 I)
- [ ] 완료하지 못한 항목을 PR 본문에 정직하게 적었다

## 배포 게이트 — PR → 운영

- [ ] 사람이 PR 을 승인했다
- [ ] dev 환경에서 확인됐다
- [ ] 마이그레이션이 있다면 덧붙이는 변경인지 확인했다 (헌법 VII)
- [ ] 운영 배포는 사람이 수동으로 dispatch 한다

---

## 구현 순서

의존성이 낮은 쪽부터. `∥` 는 병렬 가능.

```
contracts  →  mock-data  →  schema/repo  →  controller ∥ api-client  →  web
```

- **contracts** — 타입, 스키마(zod), OpenAPI 초안
- **mock-data** — 시드·픽스처. 아래 계층이 없어도 위 계층을 만들 수 있게 한다
- **schema/repo** — Prisma 스키마와 마이그레이션, 데이터 접근
- **controller** — 라우트 핸들러, 검증, 오류 매핑
- **api-client** — 프런트에서 호출하는 얇은 계층
- **web** — 페이지와 컴포넌트

거꾸로 가면(웹부터) 계약이 화면 편의에 끌려다니게 된다.
